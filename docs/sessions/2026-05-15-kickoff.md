# Session log — 2026-05-15 kickoff

Narrative record of the conversation that produced the initial repo state.
Written so a future session can pick up without re-reading the chat transcript.

## Origin

Late-night research question on 2026-05-15: *"how could I build a privacy filter for
Claude Code and other agents so personal info — emails, calendar entries, passwords etc. —
doesn't leave my machine? Maybe with a local LLM that classifies and anonymizes data
and swaps it back on the way out. Does this exist? Is it feasible? What approaches are
conceivable?"*

## Arc of the conversation

1. **Broad research** — surveyed the anonymize → LLM → de-anonymize pattern.
   Found that Microsoft Presidio, PII Shield (Microsoft), anonLLM, LiteLLM guardrails,
   and various proxy-based solutions all implement variants. The pattern is well-trodden;
   the de-anonymization step survives the LLM rewriting text around placeholders, which
   is the property that makes it actually robust.

2. **Claude Code specifics** — checked feature requests:
   - [#29434][cc29434] (redact secrets/PII from context window) — **closed as not planned**
   - [#39882][cc39882] (Pre/PostApiCall hooks) — open
   - Existing hooks (`UserPromptSubmit`, `PreToolUse`, `PostToolUse`) can **block** or
     **detect** but cannot **modify in place**
   - **Conclusion: HTTP proxy boundary is the only viable interception point** for
     Claude-Code-side work today.

3. **Why agents are harder than chat** — three problems:
   - Tool calls need the *real* value (grep, DB query, send email); placeholders break them
   - Append-only context window means once PII enters, it stays for the session
   - Proxy only sees network traffic; agent can still read sensitive local files
   The first one is the *central* unsolved problem and the differentiator for this project.

4. **Hardware / model fit** — user runs MLX, daily driver is a Qwen 35B-4bit/64k on a
   **M5 MacBook Air, 32 GB**. Decided: don't use the 35B for filtering — wrong tool
   (hot path, latency, predictability). Better: small specialized model
   (Anonymizer-SLM 1.7B / 4B, or Nemotron Privacy Filter MLX from OpenMed), under 4 GB
   combined with a GLiNER-class detector. Latency budget ≤ 1.5 s p95 stage-2.

5. **Existing-solutions deep-dive** — second pass, more targeted. Found:
   - [DontFeedTheAI][dfta] (Python/FastAPI, MIT, 544⭐): Ollama-LLM + regex dual-layer
     reverse-proxy for Claude Code, per-engagement vault, self-improving loop. Pentest-flavored.
   - [PasteGuard][pg] (TS/Bun, Apache-2.0, 630⭐): broadest agent support (ChatGPT,
     Claude/Cursor/Copilot/Windsurf/Gemini/Open WebUI). Uses Presidio. **Per fetched README,
     not reversible — verify before relying on this.**
   - [contextio][ctx] (TS, MIT, 24⭐): cleanest proxy plane, multi-tool via base-URL +
     mitmproxy chaining, working SSE reconstruction, **regex-only**.
   - [LLM-Redactor][lr] (Go, 5⭐): secrets-only, not reversible. Narrow.
   - [claude-code-local][ccl] (Python/MLX): orthogonal — replaces the cloud LLM entirely.
     Not competition; possible "ultra-private" fallback mode.
   - [OpenMed Nemotron Privacy Filter MLX][om]: building block, MLX-native, German-capable.

   **Key insight: nobody combines (a) MLX-native local LLM detection, (b) reversible
   round-trip, (c) multi-agent, (d) tool-call-boundary resolution.** (a)–(c) exist in pieces.
   (d) is unsolved everywhere.

6. **Project scaffolding** — created `~/_Code/agent-privacy-filter/`, git-init, wrote
   research docs, deferred all code.

## Decisions made (with reasoning)

| Decision | Reasoning |
|---|---|
| **Repo home:** `~/_Code/agent-privacy-filter` | Existing project convention; descriptive name; can be renamed before any release |
| **No code in first commit** | PoC's first job is model benchmarking; building proxy plumbing before knowing whether the SLM works at all is premature |
| **PoC = from-scratch, not fork** | The two unknowns (MLX SLM quality, tool-call resolver feasibility) live in code we'd write either way; proxy plumbing only worth inheriting once those unknowns are retired |
| **Phase 2 likely fork = DontFeedTheAI** | Closest conceptual match: Python, Ollama→MLX is a clean swap, dual-layer pipeline already wired, MIT |
| **Tool-call resolver flagged as central differentiator** | Nobody else does it; it's the actual hard problem; it determines whether this project is worth building or whether existing solutions are good enough |
| **License decision deferred** | MIT or Apache-2.0; not blocking PoC work |
| **Apple-Silicon-only for PoC** | Matches user hardware, avoids cross-platform tax this early |
| **Claude Code as first agent target, Cursor/Aider as second** | User priority + simplest provider (Anthropic API) to parse first |

## Key insights to carry forward

- **Don't use the 35B daily driver for filtering** — wrong shape (latency, predictability,
  size). Use specialized SLM ≤ 4B + fast detector.
- **The Presidio anonymizer/deanonymizer is mature** — pull it in for the round-trip
  plumbing regardless of detector choice. Don't reimplement.
- **GLiNER + Presidio together** is a documented pattern; Presidio supports GLiNER as
  external NLP engine. Free anonymizer/deanonymizer integration.
- **Anonymizer-SLM weight on German is unknown** — must verify at benchmark time.
  Nemotron Privacy Filter MLX explicitly supports German; potentially the safer default.
- **PasteGuard's reversibility status** is the one fact I'd double-check by reading code,
  not the README, before forking it for anything.
- **The hard problem is in the agent harness, not the proxy.** The proxy can't know that
  a token in a `tool_use.input.command` field is about to be exec'd vs. just narrative.
  Probably needs a hybrid where the proxy resolves tokens *inside* tool-call blocks before
  the agent's local executor sees them.
